# 02 — E-Paper Display

This section documents the process of connecting, understanding, and communicating with the Waveshare Pico-ePaper-4.2 display.

The goal is not only to make the display work, but to understand how the Pico communicates with the display at the hardware and software level.

## 1. Understanding the Display Interface

The Waveshare Pico-ePaper-4.2 exposes several pins used for power, SPI communication, and additional control signals.

The main pins are:

```text
VCC
GND
DIN
CLK
CS
DC
RST
BUSY
```

The SPI-related pins are:

```text
DIN → MOSI
CLK → SCK
CS  → Chip Select
```

The remaining control pins are:

```text
DC
RST
BUSY
```

I will learn the purpose of these signals before writing the display driver.

## 2. Understanding the Pins
### 2.1 SPI Pins

The display uses SPI for its main data communication.

```text
DIN → MOSI
CLK → SCK
CS  → Chip Select
```

#### DIN — Data In

`DIN` is the display's SPI data input.

It receives data from the Pico's MOSI signal.

```text
Pico MOSI ─────────→ DIN
```

The Pico sends bytes through this connection using the SPI hardware.

#### CLK — Clock

`CLK` receives the SPI clock generated by the Pico.

```text
Pico SCK ──────────→ CLK
```

The clock provides the timing that allows the display to determine when to sample the data on DIN.

#### CS — Chip Select

`CS` selects the display for an SPI transaction.

The display uses an active-low CS signal:

```text
CS HIGH → display not selected
CS LOW  → display selected
```

CS is controlled separately from the SPI data transfer.

### 2.2 DC — Data/Command

`DC` stands for **Data/Command**.

SPI itself only defines how bits are transferred. It does not define what those bytes mean.

The e-paper controller therefore uses the DC signal to distinguish between commands and data.

```text
DC LOW  → Command
DC HIGH → Data
```

For example:

```text
DC LOW
   ↓
Send SPI byte
   ↓
Display interprets byte as a command
```

while:

```text
DC HIGH
   ↓
Send SPI bytes
   ↓
Display interprets bytes as data
```

This means that the same byte could have a different meaning depending on the state of DC.

DC is not part of the SPI protocol itself. It is an additional GPIO control signal used by the e-paper controller.

### 2.3 RST — Reset

`RST` is the reset signal for the e-paper controller.

It allows the Pico to force the display controller back into a known initial state.

The reset signal is active-low:

```text
RST LOW
   ↓
Reset controller

RST HIGH
   ↓
Normal operation
```

During display initialization, the Pico can generate a short reset pulse before configuring the display.

RST is another GPIO control signal and is separate from SPI.

### 2.4 BUSY — Display Status

`BUSY` works in the opposite direction from most of the other control signals.

Instead of the Pico telling the display what to do, the display uses BUSY to tell the Pico about its current state.

```text
E-paper ─────────→ Pico
          BUSY
```

When the display is performing an operation such as refreshing the screen, it may indicate that it is busy.

The Pico can read this signal using a GPIO input:

```python
busy.value()
```

This is conceptually similar to reading the state of a physical button.

The difference is that instead of a person changing the electrical state of the GPIO, the e-paper controller changes the BUSY signal.

The general sequence is:

```text
Pico:
"Refresh the display."

        ↓

E-paper:
"I'm busy."

        ↓

Pico waits

        ↓

E-paper:
"I'm finished."

        ↓

Pico continues
```

### 2.5 Power

The remaining pins provide the electrical connections required by the display:

```text
VCC → Power
GND → Ground
```

`GND` provides the common electrical reference between the Pico and the display.

### 2.6 Complete Interface

The complete interface can therefore be understood as:

```text
                    E-PAPER
                       │
       ┌───────────────┴───────────────┐
       │                               │
      SPI                            Control
       │                               │
 ┌─────┼─────┐                  ┌─────┼─────┐
 │     │     │                  │     │     │
DIN   CLK    CS                 DC    RST   BUSY
 │     │     │                  │     │     │
MOSI  SCK   Select            Command Reset Status
 │     │     │                  │     │     │
 └─────┴─────┘                  └─────┴─────┘
       │                               │
       └──────────── Pico ─────────────┘
```

The main communication path is therefore:

```text
Pico
 ↓
SPI hardware
 ↓
MOSI / SCK / CS
 ↓
E-paper SPI interface
 ↓
E-paper controller
```

while DC, RST, and BUSY provide additional control and status information.

Understanding these signals is important before wiring the display because each pin has a different role and direction.
